# Capsule ModuleImportEnvelope schema

Return one top-level JSON object.
Do not wrap it in markdown.
Do not include JSON comments or trailing commas.

This skill returns one run for one Capsule draft. The canonical output is a full `ModuleImportEnvelope` for the CMS drafting import path.

## Top-level fields

Required:

- `schema_version`: string, normally `"1.0"` unless the caller supplies a different accepted version
- `module_name`: string, normally `"capsule-draft-writer-edt-prf"`
- `module_type`: string, must be `"drafting"`
- `run_id`: string, copied from `meta.run_id` or supplied run identity when available
- `result_status`: `"success"` | `"partial_success"` | `"failed"`
- `warnings`: array of warning objects; use `[]` when there are no warnings
- `meta`: object copied from input `meta` when available
- `payload`: object for `success` and `partial_success`; `null` for `failed`

Optional:

- `trace`: object for non-payload audit detail such as `source_completion` or `claim_source_map`
- `open_questions`: array of strings or short objects
- `draft_blocked_reason`: string, required when `result_status` is `"failed"`

## `meta`

Return top-level `meta` on every run, including `failed`.
Treat input `meta` as the provenance truth source and echo it into output `meta` when possible.
Preserve unknown extra `meta` fields rather than dropping them.

For normal app-driven runs, `meta` should include at least:

- `generated_at` when supplied or safely generated by caller context
- `object_type`, normally `"topic_prototype"`
- `object_id`
- `context_pack_id`
- `language`
- `market`
- `format_variant`
- `skill_name`
- `skill_version`

Optional when present:

- `skill_build_ref`
- other caller-provided metadata

### `skill_name` rule

Use the canonical skill name `"capsule-draft-writer-edt-prf"`.
If input `meta.skill_name` is missing, set it to that canonical value in output.
If other provenance fields are missing, return the available `meta` object, add a warning, and downgrade status when needed rather than inventing values.

## Payload for `success` and `partial_success`

For importable runs, place Capsule fields directly under `payload`.
Do not nest the Capsule under another object.

Required payload fields:

- `object_type`: must be `"capsule"`
- `topic_prototype_id`: copied from the target prototype DB ID when supplied
- `editorial_profile_id`: copied from the applied editorial profile DB ID when supplied
- `title`: consumer-friendly Capsule headline
- `citation_line`: editor-facing formal short citation line, or `null` only with a warning when source metadata is insufficient
- `big_picture`: reader-relevance opening section
- `whats_new`: main new finding or source-backed update
- `by_the_numbers`: the most memorable supported numbers
- `why_it_matters`: editorial significance of the finding
- `yes_but`: evidence caveat plus practical caveat where support allows
- `what_it_means_for_you`: cautious, useful reader takeaway
- `language`: output language code or label copied from `meta.language` or requirements
- `format_variant`: copied from `meta.format_variant` or output requirements; default to `"standard_newsletter"` when the app expects it
- `status`: normally `"draft"`
- `word_count`: integer count of the six body sections only
- `reference_ids`: array of supplied source IDs used in the draft

Recommended payload fields:

- `external_ref`: deterministic upsert key when enough IDs are available, e.g. `"capsule-draft-cp-17-tp-3"`
- `source_note`: short internal note, not a public section

### Payload field whitelist

The canonical payload should contain only the fields defined above plus caller-approved extensions.
Legacy mini-essay fields from earlier schema versions are not part of the canonical payload.

## Field-level rules

### `title`

Use a concrete, consumer-friendly headline.
Aim for 4-8 words in English unless the target language naturally requires otherwise.
Keep it memorable but medically responsible.

### `citation_line`

`citation_line` should be a formal short citation, not a narrative source summary.
Prefer one primary source that best supports the Capsule's central editorial angle.
Prefer peer-reviewed sources over official statistics when the central claim is clinical, scientific, or translational.
Use only metadata supplied in the Context Pack or completed from approved-source lookup when `source_policy.mode` allows it.
Do not invent author names, volume, issue, pages, article numbers, dates, or publisher details.

Preferred format when metadata is available:

`Author(s). Journal/Publisher. Year;volume(issue):pages or article number.`

Fallback order:

1. `Author(s). Journal/Publisher. Year.`
2. `Journal/Publisher. Year. Title.`
3. `Title. Journal/Publisher. Year.`
4. `Publisher. Title. Year.`

For official statistics, use a compact publisher-title-year citation, e.g. `National Bureau of Statistics of China. Statistical Communique of the People's Republic of China on the 2025 National Economic and Social Development. 2026.`
If multiple sources are essential in the displayed citation line, separate short citations with semicolons.
Do not start with `Sources:` unless the supplied and allowed lookup metadata are too incomplete for any formal citation.
Keep supplemental sources in `reference_ids`, `source_note`, or `trace` rather than overloading `citation_line`.

If no reliable citation line can be produced, set `citation_line` to `null`, return `partial_success`, and include a warning with `affected_fields: ["citation_line"]`.

### Six body sections

Each body section should be one compact paragraph.
Use plain, reader-facing language.
Do not add visible section labels inside field values.

### `by_the_numbers`

Use actual numeric facts that help the reader understand scale, timing, duration, population, exposure, comparator, or effect size.
Do not use this field merely to list source anchors, publication years, evidence types, or datasets.
If no meaningful supported numbers are available, keep the field short, avoid pretending source labels are numbers, and use `partial_success` or a warning when review is needed.

### `word_count`

Count only words in:

- `big_picture`
- `whats_new`
- `by_the_numbers`
- `why_it_matters`
- `yes_but`
- `what_it_means_for_you`

Do not count `title`, `citation_line`, `source_note`, metadata, or trace fields.
Target 180-280 words across the six sections unless `embedded_runtime_config.output_requirements` says otherwise.
Use 330 words as a hard upper guide unless the caller overrides it.

### `reference_ids`

Use numeric source IDs when supplied by the ContextPack.
If numeric IDs are not supplied, use string IDs only when they exactly match supplied Source external references.
Do not invent IDs such as `src_01` unless the input reference set uses that exact external reference.
Include only source IDs that support claims actually used in the final draft.

## `trace`

Use `trace` for audit information that should not be imported into the Capsule payload.
Do not include `claim_source_map` or `source_completion` in `payload`.

### `trace.source_completion`

When `approved_source_lookup` supplies facts or metadata that were not explicitly present in the packed summary, include `trace.source_completion`. When `approved_source_lookup` is enabled but lookup is skipped, unavailable, or produces no usable completion, record a concise decision or fallback item in `trace.source_completion` when the caller allows trace output.
Each object should be compact and reviewable. `source_locator` must be a plain URL, DOI, or approved locator string, not a Markdown link. If the locator is unavailable, use a short plain-text fallback such as `approved source locator unavailable in execution environment`.

```json
{
  "source_id": 84,
  "action": "numeric_fact_extracted",
  "extracted_value": "108 adults aged 25-75; shifts around ages 44 and 60",
  "fields_used": ["study_population", "age_range", "age_shift_points"],
  "used_in": ["by_the_numbers"],
  "source_locator": "https://doi.org/10.1038/s43587-024-00692-2"
}
```

Allowed `action` values include:

- `citation_metadata_extracted`
- `numeric_fact_extracted`
- `lookup_attempted_no_usable_completion`
- `lookup_unavailable_fallback_used`
- `lookup_not_needed_packed_fields_sufficient`

Use `trace.source_completion` for transparency, not as a warning.
Add a warning only when the completion is missing, uncertain, conflicting, inaccessible, or creates review risk.

### `trace.claim_source_map`

Do not include `claim_source_map` in `payload` by default.
If `output_requirements.request_claim_source_map` is true, or if the caller asks for traceability, include:

```json
{
  "trace": {
    "claim_source_map": [
      {
        "claim_id": "c1",
        "claim_excerpt": "...",
        "reference_ids": [1],
        "support_level": "direct"
      }
    ]
  }
}
```

Allowed `support_level` values:

- `direct`
- `qualified`
- `contextual`

## Warning object

Use this structure:

```json
{
  "code": "claim_support_gap",
  "severity": "medium",
  "message": "one sentence explaining the risk.",
  "affected_fields": ["yes_but"]
}
```

Required warning fields:

- `code`
- `severity`: `"low"` | `"medium"` | `"high"`
- `message`

Optional warning fields:

- `affected_fields`: array of payload, meta, or trace field names
- `reference_ids`: array of source IDs related to the warning

## Result status rules

### `success`

Use when all required fields are present, the draft is safe and supported, and warnings are absent or only low severity.
Set `payload.status` to `"draft"`.
Approved-source lookup completion may still be `success` when completed facts are traceable and not uncertain.

### `partial_success`

Use when a complete importable payload can be produced but human review is needed because of incomplete citation metadata, thin support, inaccessible approved lookup, source ambiguity, weak `by_the_numbers`, section-boundary risk, format risk, or non-critical provenance gaps.
Set `payload.status` to `"draft"`.
Include warnings.
`partial_success` is intended to be importable when required payload fields and references are valid.

### `failed`

Use only when a safe importable draft cannot be produced.
Set `payload` to `null`.
Include `draft_blocked_reason` and at least one warning.
Do not return an empty payload object as a failed draft.

## Failure rules

Return `failed` when:

- the topic prototype is missing or not interpretable
- the reference set cannot support the central approved angle
- required identifiers are absent and no safe importable payload can be built
- medical safety would require too much unsupported inference
- the requested output would require new sources, open research, diagnosis, treatment advice, or causal claims not supported by the approved references
